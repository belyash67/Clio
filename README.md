# CLIO

> **Текущее состояние — 14 ноября 2026:** приложение открыто на https://clio.alwaysdata.net. Срок доступа ограничен до 14 декабря 2026, после чего сервер закроет работу с приложением без автоматического удаления данных. Технический запуск не означает завершения юридической подготовки. Внутренние заметки и настройки размещения не входят в публичный исходный код. [Правила публикации исходников](docs/publication.md). Ниже сохранены концепция и исторический отчёт прежнего запуска.

**Your stories. Your cinema. Your community.**

Clio — социальная PWA-платформа для любителей фильмов, сериалов и анимации. Пользователи открывают произведения, ведут личную библиотеку и кинодневник, ставят оценки, пишут рецензии, собирают коллекции и общаются с друзьями.

> **Статус:** 14 ноября 2026 сайт опубликован: **https://clio.alwaysdata.net**. Приложение и PostgreSQL работают на alwaysdata Free независимо от компьютера владельца. Два существующих аккаунта и данные перенесены с проверкой содержимого таблиц; активные сессии и одноразовые ссылки не переносились. Владелец подтвердил открытие сайта и постеров на телефоне в мобильной сети РФ без VPN. Локальные сценарии и мобильный Chrome проверены; доставка писем в почтовый ящик, другие российские сети, реальные устройства и требования к персональным данным остаются отдельными проверками. Подробности: [публичный запуск](docs/public-launch.md), [отчёт QA](docs/qa-report.md). Ниже сохранена полная концепция, включая будущие функции.

## Локальный запуск

Все файлы приложения находятся в этой папке Clio. Запуск: `npm.cmd run dev`, затем открыть http://localhost:3000. Для просмотра начального интерфейса регистрация в сервисах не нужна. Настройка настоящих аккаунтов: [инструкция для Windows](docs/local-setup.md).

Код: `src/app` — страницы, `src/components` — общие элементы интерфейса, `src/modules` — функции платформы, `src/server` — сервер, БД, почта и TMDB, `src/i18n` — переводы. Проверки: `npm.cmd run lint`, `npm.cmd run typecheck`, `npm.cmd test`, `npm.cmd run test:db`, `npm.cmd run test:e2e`, `npm.cmd run build`. Тесты БД создают и удаляют только собственные изолированные схемы. Браузерные тесты: [устройство и запуск](docs/browser-testing.md).

## 1. Зафиксированные решения

- **Аудитория:** сначала владелец и друзья, с возможностью роста.
- **Регистрация:** открытая для всех, с подтверждением email и защитой от спама.
- **Стоимость:** разработка, запуск и эксплуатация должны обходиться в **0 ₽**, хотя бы на начальном этапе. Не подключать платные услуги, пробные тарифы с автоматическим списанием или банковские карты без отдельного согласия владельца.
- **Доступность:** друзья из России должны иметь возможность использовать приложение **без VPN**. Это необходимо проверять из российских сетей; доступность конкретного провайдера нельзя считать гарантированной.
- **Платформы:** iOS, Android, Windows, macOS через адаптивное PWA, без обязательной публикации в магазинах.
- **Стиль:** минимализм, кинематографическая атмосфера, тёмная тема по умолчанию, светлая и системная темы.
- **Процесс:** сначала архитектура и схема БД, затем реализация небольшими проверяемыми этапами. Никаких фальшивых работающих функций.

## 2. Технологии (предварительный выбор)

| Слой | Выбор |
|---|---|
| Frontend | Next.js, React, TypeScript, Tailwind CSS, Lucide |
| Сервер | Next.js Server Actions и Route Handlers |
| БД | PostgreSQL, Drizzle ORM, SQL-миграции |
| Авторизация | Better Auth или другое проверенное решение с PostgreSQL |
| Каталог | TMDB API с серверным кэшированием |
| Файлы | Абстракция S3-совместимого хранилища; до подключения — стандартные аватары и постеры TMDB |
| Контроль версий | Git + GitHub |
| Размещение | alwaysdata Free: Node.js + PostgreSQL, публичный адрес `clio.alwaysdata.net`; лимиты и проверки — в [инструкции](docs/public-launch.md) |

Amvera Managed PostgreSQL рассматривалась ранее, но не подключалась. Для локальной разработки используется PostgreSQL на компьютере. Для публичной версии владелец зарегистрировал alwaysdata и предоставил API-токен через исключённый из Git локальный файл. API подтвердил тариф Free, а владелец — открытие сайта и постеров в своей российской мобильной сети. Платные услуги и изменения тарифов не выполнялись. Доступность во всех сетях и юридическое соответствие не гарантируются.

Секреты хранятся только в переменных окружения на сервере. Основные пользовательские данные не хранятся только в localStorage. Не сохранять изображения в PostgreSQL как бинарные данные. Использовать обычный PostgreSQL без привязки к специфичным функциям провайдера.

## 3. Продуктовые модули

### 3.1 Аккаунты и профили

- Регистрация: уникальный username, email, пароль и подтверждение пароля.
- Вход, выход, подтверждение email, восстановление и смена пароля, безопасные сессии.
- Профиль: аватар, обложка, username, отображаемое имя, био, дата регистрации, любимые жанры, статистика, рецензии, коллекции.
- Возможность закрепить четыре любимых фильма (предложение, требует окончательного утверждения).
- Приватность профиля, библиотеки и активности.
- Роли и права определяются на сервере; пользователь не может назначить себе роль администратора.

### 3.2 Общий каталог

- Фильмы, сериалы, аниме, мультфильмы.
- TMDB: названия, оригинальные названия, описание, постеры, даты, страны, жанры, продолжительность, актёры и режиссёры.
- Отдельно показывать рейтинг Clio и рейтинг TMDB.
- Поиск по названию, оригинальному названию, актёрам, режиссёрам и жанрам.
- Фильтры: жанр, год, страна, тип, рейтинг; сортировка: популярность, рейтинг, дата, алфавит.
- Аниме и мультфильмы в TMDB требуют собственной классификации: не считать их независимыми базовыми типами TMDB.
- Уникальность произведения определять по паре `(tmdb_media_type, tmdb_id)`, чтобы не путать ID фильма и сериала.
- Кэшировать метаданные и обновлять их по понятной политике; не обращаться к TMDB при каждом просмотре страницы.
- Проверить лицензию, атрибуцию и ограничения TMDB до публикации.

### 3.3 Личная библиотека и кинодневник

- Основные статусы: Watched, Watching, Watch Later, Dropped.
- Favorites — независимый признак: произведение может быть избранным при любом статусе.
- Фильтры, сортировка, поиск, даты и история просмотров.
- Пересмотры и записи кинодневника рассматриваются как отдельные события, а не дубликаты произведений.
- **Не решено:** хранить одну текущую оценку на произведение или отдельные оценки по просмотрам. До решения не фиксировать несовместимую схему БД.
- В дальнейшем: прогресс сезонов и эпизодов.

### 3.4 Оценки и рецензии

- Предварительная шкала оценок 1–10; шаг 0.5 обсуждался, но ещё не утверждён.
- Рецензии: создание, редактирование, удаление, лайки и комментарии.
- Не допускать изменения чужих оценок и рецензий.
- Рейтинг Clio должен учитывать объём оценок, чтобы единичная высокая оценка не искажала сортировку.

### 3.5 Социальная система

- Поиск пользователей, запросы в друзья, принятие, отклонение, удаление.
- Лента разрешённой активности: оценки, рецензии, коллекции и т. д.
- Подписки, реакции и совместные коллекции предложены для будущих версий, но не утверждены как обязательные для первой.
- Настройки приватности должны применяться в серверных запросах.

### 3.6 Коллекции

- Создание, редактирование, удаление, описание, обложка, порядок произведений.
- Видимость Public / Private.
- Проверка прав владельца коллекции на сервере.

### 3.7 Уведомления

- Запросы и принятие дружбы, лайки, комментарии, ответы.
- Push-уведомления — отдельный этап с учётом ограничений платформ и PWA.

### 3.8 Статистика и рекомендации

- Число просмотренных фильмов и сериалов, средняя оценка, жанры, история просмотров, активность по месяцам.
- Сначала простые объяснимые рекомендации по оценкам, жанрам, библиотеке и избранному; позднее учитывать интересы друзей.
- Clio Wrapped — будущий этап.

### 3.9 Совместный выбор фильма

- Комнаты, участники, предложения, голосование, результаты и победитель.
- Без трансляции фильмов.
- Не входит в первый релиз.

### 3.10 Настройки

- Account: email, пароль, сессии, удаление аккаунта.
- Profile: username, имя, био, аватар, обложка.
- Appearance: Dark, Light, System.
- Language: русский, английский, немецкий. Язык интерфейса не переводит автоматически публикации пользователей.
- Privacy: профиль, библиотека, активность.
- Notifications: предпочтения уведомлений.

### 3.11 Административная панель

- Пользователи и роли, блокировки, модерация рецензий и комментариев, жалобы, исправление данных каталога, статистика.
- Проверки полномочий только на сервере; скрытие кнопки не является защитой.
- Минимальная модерация нужна уже при открытой регистрации.

## 4. Навигация и интерфейс

Основной формат — телефон. Внизу остаются пять вкладок; внутри каждой сначала показывается основное содержимое. Фильтры и редакторы открываются в нижних панелях, лента/друзья/поиск разделены, настройки вынесены из профиля на отдельный экран. Схема и проверка обновлённого интерфейса: [мобильный интерфейс](docs/mobile-interface.md).

Основные разделы концепции: Home, Catalog, Search, My Library, Community, Collections, Notifications, Profile, Settings. Конкретную информационную архитектуру и число вкладок нужно упростить для мобильного интерфейса.

- На мобильных устройствах — нижняя навигация; на десктопе — боковая панель.
- Home: популярное, новинки, рекомендации, друзья, недавние просмотры, продолжение сериалов (по мере готовности модулей).
- Страница произведения: постер, метаданные, рейтинги, описание, актёры, режиссёр и действия пользователя.
- Плавные, но доступные анимации; учитывать `prefers-reduced-motion`.
- Загрузка реальных данных, состояния пустых списков, ошибки и скелетоны загрузки.

## 5. База данных: предварительные сущности

Окончательную ER-диаграмму и ограничения спроектировать **до реализации**.

- Auth: `users`, таблицы сессий/аккаунтов/верификации по выбранной auth-библиотеке, `user_settings`, `user_roles`.
- Catalog: `media`, `genres`, `media_genres`, `people`, `media_people`.
- Library: `user_library`, `favorites` (или эквивалентный независимый признак), `watch_history`, `ratings`, `reviews`.
- Social: `friendships`, `comments`, `likes`, `activity`, `notifications`.
- Collections: `collections`, `collection_media`.
- Moderation: `reports`.
- Later: `watch_rooms`, `watch_room_members`, `watch_room_suggestions`, `watch_room_votes`.

Нужны PK/FK, уникальные ограничения, индексы по частым запросам, ограничения целостности, миграции и резервное копирование. Уточнить правила удаления данных и каскадов. Не дублировать сущности без необходимости.

## 6. Безопасность и конфиденциальность

- HTTPS в опубликованной версии, безопасное хеширование паролей, защищённые cookie и сессии.
- Проверка прав и валидация данных на сервере, параметризованные запросы через ORM.
- Ограничение частоты регистрации, входа и публичных действий, защита от спама.
- Секреты только в серверном окружении; `.env*` с секретами не коммитить.
- Нельзя менять чужую библиотеку, оценки, коллекции, рецензии и настройки.
- Удаление аккаунта и пользовательских данных по запросу.
- Перед публичным запуском проверить применимые требования к персональным данным, особенно для пользователей из России; не заявлять о соответствии без проверки.
- Проверить лицензии и атрибуцию сторонних данных и изображений.

## 7. PWA и производительность

- HTTPS, manifest, иконки, установка на домашний экран, корректная работа Safari/Chrome.
- Splash screen и возможности установки — с учётом реальных ограничений платформ.
- Обновления без переустановки; стратегия service worker и кэширования не должна оставлять устаревшие приватные данные.
- Пагинация, lazy loading изображений, индексы, серверное кэширование, оптимизированные запросы.
- Не обещать полноценный offline-режим или push до отдельной реализации.

## 8. Этапы

1. Уточнить спорные решения, архитектуру, бесплатное размещение и критерии проверки доступности из РФ.

4. Поднять локальный PostgreSQL и выполнить миграции.
5. Реализовать авторизацию, email-поток, профиль и базовые настройки.
6. Интегрировать TMDB, каталог, страницу произведения и поиск.
7. Реализовать личную библиотеку, кинодневник и оценки.
8. Добавить рецензии, коллекции и базовую модерацию.
9. Добавить дружбу, ленту и уведомления.
10. Статистика и простые рекомендации.
11. Проверить PWA, безопасность, мобильные сценарии, доступность из РФ и бесплатное размещение.
12. Позднее: комнаты, расширенная статистика, Wrapped, push, расширенные социальные функции.

Каждый этап завершается проверкой и согласованием до перехода к следующему.

## 9. Критерии первой рабочей версии

- Регистрация, вход и восстановление доступа работают.
- Данные сохраняются в PostgreSQL; каталог общий, библиотека индивидуальна.
- Интеграция TMDB, оценки, рецензии и коллекции работают на реальных данных.
- Серверная авторизация и базовая модерация защищены.
- Приложение адаптировано для телефонов и компьютеров и устанавливается как PWA.
- Пользователи из РФ могут пройти ключевые сценарии без VPN (подтверждено реальными проверками).
- Нет обязательных платежей и автоматического перехода на платный тариф.

## 10. Решения и оставшиеся проверки

Владелец поручил агенту выбирать решения в рамках концепции, уточняя конкретные детали по мере необходимости. Приняты следующие решения; они уточняют предварительные формулировки выше:

- Одна текущая оценка на произведение, история изменений отдельно; просмотры и пересмотры — отдельные события.
- Шкала 1–10 с шагом 0.5.
- Next.js + PostgreSQL + Drizzle + Better Auth; совместимые версии фиксируются перед установкой.
- Дружба, лента, комментарии и лайки рецензий, внутренние уведомления входят в первую публичную версию, но реализуются после личной библиотеки.
- Профиль всегда доступен подтверждённым друзьям, по умолчанию — friends; настройка «Все» открывает его остальным и добавляет в поиск. Библиотека и активность по умолчанию private; рецензии и коллекции сохраняют отдельные ограничения. Принятый друг не получает доступ к личному контенту автоматически.
- Русский интерфейс сначала; английский и немецкий — до первого публичного релиза.
- Загрузка аватаров/обложек и закрепление четырёх фильмов отложены.

Подробности: [архитектура](docs/architecture.md), [модель данных и ER-диаграмма](docs/data-model.md), [первый этап разработки](docs/stage-1.md).

Реализация каталога: [этап 2 — TMDB](docs/stage-2.md). Последующее завершение локальной версии: [реализованные функции и проверки](docs/completion-plan.md).

**Требуют проверки:** настоящая доставка email после размещения, другие российские сети, реальные iOS/Android и требования к персональным данным, включая место хранения данных. Условия бесплатного тарифа и его пригодность при росте нужно проверять повторно; текущие результаты — в [отчёте запуска](docs/public-launch.md).

Владелец разрешил завершить оставшиеся функции первой версии одной задачей, а затем поручил агенту самостоятельную проверку и явно разрешил установку Playwright. Работа выполнена в этой папке. 14 ноября владелец поручил открыть профили для подтверждённых друзей и запустить сайт для общего пользования в рамках бюджета 0 ₽. Это разрешение на публичный запуск приложения, без изменения приватности репозитория и без платных услуг.

Владелец отдельно подтвердил назначение аккаунта **@morrov** постоянным администратором и индивидуальную галочку «Создатель Clio». Галочка хранится отдельно от роли, не выдаётся другим администраторам автоматически и недоступна для самостоятельного изменения через настройки или auth API. Панель: `/admin`; остальные пользователи доступа к ней не имеют. Первичное назначение владельца выполняется локальным скриптом `npm.cmd run admin:grant -- <подтверждённый_username>` только после явного согласия владельца.
