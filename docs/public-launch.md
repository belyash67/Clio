# Публичный запуск Clio — 14 ноября 2026

> **Обновление:** после временной паузы сайт вновь открыт по прямому поручению владельца на ограниченный срок. Ниже отчёт первоначального размещения; детальный журнал возобновления хранится отдельно от публичных исходников.

Адрес: **https://clio.alwaysdata.net**. Приложение работает на хостинге независимо от компьютера владельца. Для входа используются прежние username/email и пароль. Публичная и локальная базы теперь независимы: новые записи на сайте не появляются автоматически в localhost, повторно заливать локальную БД поверх публичной нельзя.

## Размещение и доступ

- alwaysdata, аккаунт `clio`, продукт `plus-free` (API подтвердил Free: 1 ГБ диска, 256 МБ RAM, 0.25 CPU). Платные ресурсы, смена тарифа и trial не подключались. Владелец самостоятельно зарегистрировал аккаунт и предоставил API-токен через локальный файл.
- Node.js 24; сайт типа Node.js, рабочая папка `clio-releases/standalone`, запуск `node --env-file=.env.production server.js`. `HOSTNAME=::`, порт предоставляет платформа; ограничение heap 160 МБ. HTTPS принудительный, кэширование личных HTTP-ответов на прокси выключено.
- PostgreSQL 18, отдельная БД `clio_app` и пользователь приложения; `sslmode=verify-full`. Фактический TLS 1.3 проверен. Основные сессии и права остаются в PostgreSQL, логика не привязана к провайдеру.
- Технический пользователь SSH отдельный. Конфигурация `.env.production` на сервере доступна только техническому пользователю и группе этого же аккаунта (640), чтобы её мог читать процесс сайта. В HTTP она недоступна. Токен API, служебные пароли и резервная копия находятся в исключённых из Git `.env.hosting.local` и `.runtime/`; в архив исходников и серверный пакет они не входят.
- По API провайдера дата-центр — **Paris 1, France**. Юридическая готовность открытого сервиса пока не подтверждена: требуется отдельная проверка требований к персональным данным, месту их хранения, трансграничной передаче и уведомлениям/документам оператора. Это оставшееся требование README; техническая публикация его не закрывает.

Условия провайдера нужно проверять повторно при росте: [тарифы](https://www.alwaysdata.com/en/offers/), [лимиты Free](https://help.alwaysdata.com/en/admin-billing/billing/public-cloud-prices/), [ограничения непроверенных аккаунтов](https://help.alwaysdata.com/en/docs/admin-billing/profile/restricted-mode/). Не выбирать платный тариф для снятия ограничений без решения владельца.

## Перенос и правило дружбы

Сделана согласованная резервная копия локального PostgreSQL. В новую пустую БД восстановлены схема и данные; количество и контрольные суммы 20 таблиц совпали с экспортированным снимком. Перенесены два существующих аккаунта, хеши паролей, роли, галочка создателя и пользовательские данные. Активные сессии, лимиты запросов и одноразовые токены не копировались; на новом адресе нужен новый вход и свежие ссылки подтверждения/сброса.

Подтверждённые друзья всегда открывают профиль. Настройки профиля: «Друзья» и «Все»; миграция 0007 переводит прежний private в friends и меняет default. Сервер также трактует старое private или отсутствие настроек как friends. В ожидании запроса и после удаления дружбы доступ к friends закрыт; блокировка аккаунта сохраняет приоритет. Приватная библиотека, активность и личные рецензии не становятся доступными другу автоматически. Поиск по-прежнему показывает только публичные профили.

## Обновление и восстановление

Полная `npm ci` на бесплатном сервере превысила лимит памяти, поэтому сборка выполняется в папке Clio на компьютере:

1. Проверить код и выполнить `npm.cmd run build`.
2. При обновлении sharp скачать именно соответствующие версии Linux-пакетов из `node_modules/sharp/package.json` через `npm.cmd pack --ignore-scripts --pack-destination .runtime <пакеты>` и распаковать в `.runtime/native-linux/node_modules/@img/`. Для текущей версии: `@img/sharp-linux-x64@0.35.5`, `@img/sharp-libvips-linux-x64@1.3.4`.
3. `npm.cmd run package:hosted` создаёт `.runtime/hosted-release`: включает standalone, public и static, проверяет версии Linux-модулей, исключает env-файлы и непереносимые ссылки. Генерируемая папка проверяется перед заменой, посторонняя папка не удаляется.
4. Загрузить пакет в новую папку релиза по SFTP, отдельно перенести текущую серверную конфигурацию с правами 640, проверить запуск и миграции, затем переключить рабочую папку сайта. Перед изменениями БД сохранить свежую копию именно публичной базы. Не восстанавливать прежний локальный снимок при обычном обновлении.
5. Проверить каталог, вход, запись данных и HTTPS, оставить предыдущий релиз для отката приложения. Миграции БД не откатывать разрушительными командами автоматически.

Локальная копия `.runtime/clio-backup.dump` была восстановлена и сверена при этом запуске. Проверка восстановления из автоматических резервных копий самого провайдера — отдельная задача; не считать её выполненной по факту наличия тарифа.
