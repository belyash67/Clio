# Локальный запуск Clio в Windows

Файлы приложения находятся непосредственно в папке Clio. Открывай эту папку в VS Code. В командах используется npm.cmd, чтобы не менять политику выполнения PowerShell.

## 1. Посмотреть интерфейс

В терминале VS Code, находясь в Clio:

```powershell
npm.cmd run dev
```

Открой http://localhost:3000. Остановить сервер: Ctrl+C в этом терминале. Вход и регистрация отключены, пока не заполнены серверные настройки. Наличие настроек само по себе не подтверждает работоспособность БД и доставки писем.

Если сервер запускает агент в ограниченной среде, для SMTP нужен запуск с разрешённым сетевым доступом: иначе возможен DNS timeout, даже когда отдельная SMTP-проверка вне ограничений проходит. При обычном запуске из терминала владельца это разрешение среды агента не применяется. Не отключай TLS и не меняй защиту аккаунта для обхода сетевой ошибки.

## 2. Установить PostgreSQL

Для автоматической настройки после установки агент подготовил `.env.local`. Впиши пароль пользователя postgres в строку `POSTGRES_ADMIN_PASSWORD` между двойными кавычками и сохрани файл (если пароль содержит кавычку или обратную косую черту, сообщи только об этом, без самого пароля). Затем можно запустить `npm.cmd run db:setup`: скрипт создаст отдельную роль clio без административных прав, базу, применит миграции и проверит семь таблиц. После успеха пароль postgres удаляется из файла. Существующие роли и базы скрипт не перезаписывает. SMTP настраивается отдельно.

Ниже — ручной вариант, если автоматическая настройка не используется.

Официальная страница: https://www.postgresql.org/download/windows/

Нажми Download the installer и выбери стабильную PostgreSQL 18 для Windows x64. Нужны PostgreSQL Server, pgAdmin и Command Line Tools. Оставь порт 5432, сохрани пароль пользователя postgres у себя; Stack Builder не требуется. Если порт занят, используй выбранный установщиком порт и в DATABASE_URL.

В pgAdmin подключись к локальному серверу. Через Login/Group Roles → Create создай пользователя clio с отдельным паролем. На вкладке Privileges включи Can login, оставь выключенными Superuser, Create roles и Create databases. Через Databases → Create создай базу clio, Owner — clio. Приложение не должно подключаться от суперпользователя postgres.

## 3. Подготовить локальные секреты

Скопируй .env.example в .env.local в корне проекта. Если .env.local уже есть, не перезаписывай его.

- DATABASE_URL: postgresql://clio:ПАРОЛЬ@localhost:5432/clio. Специальные символы пароля должны быть закодированы для URL.
- BETTER_AUTH_URL: http://localhost:3000 — используй именно этот адрес и в браузере.
- BETTER_AUTH_SECRET: сгенерируй командой ниже и вставь результат только в свой .env.local.

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Пароли, токены и содержимое .env.local не отправляй в чат и не загружай на GitHub. Файл исключён из Git; .env.example содержит только образец.

## 4. Подключить почту

Нужен реальный SMTP-сервер для подтверждения email и восстановления доступа. Платный сервис не подключён. Можно использовать SMTP существующего почтового аккаунта, если его правила допускают такую отправку; потребуется отдельный пароль приложения, а не основной пароль ящика. Порядок настройки проверяется для конкретного провайдера.

Заполни SMTP_HOST, SMTP_PORT (465 для TLS или 587 для STARTTLS), SMTP_USER, SMTP_PASSWORD и SMTP_FROM (email отправителя). Без настроенной почты регистрация недоступна. После изменения .env.local перезапусти dev-сервер.

## 5. Подготовить таблицы

После создания БД и заполнения DATABASE_URL:

```powershell
npm.cmd run db:check
npm.cmd run db:migrate
npm.cmd run db:check
```

Первая миграция создаёт семь таблиц и тип приватности. Она предназначена для новой БД Clio. Не применяй её к посторонней базе. db:generate нужен при изменении схемы, для обычного первого запуска достаточно db:migrate.

## 6. Проверить настоящий сценарий

1. Зарегистрируйся с собственным email и подтверди адрес через письмо.
2. Войди, измени имя, био и приватность, обнови страницу и проверь сохранение.
3. Выйди; /profile должен перенаправлять на вход.
4. Запроси восстановление пароля, установи новый пароль; старый пароль должен перестать работать.
5. В другом браузере проверь отзыв остальных сессий и отсутствие доступа к чужим данным.

Пока БД и почта не подключены, этот сценарий не считается проверенным.

## Проверки проекта

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run test:db
npm.cmd run build
```

test:db требует настроенную PostgreSQL с применёнными миграциями. Тест счётчика откатывает записи транзакцией. Auth-тест создаёт отдельную схему clio_test_<случайный UUID>, применяет к ней все миграции, проверяет регистрацию, подтверждение email, вход и сброс пароля, затем удаляет только эту тестовую схему. Письма перехватываются исключительно в тесте; реальные аккаунты и таблицы public не изменяются auth-тестом. Нужны права создания схем в локальной базе (у владельца clio они есть). Реальная доставка писем проверяется отдельно. PWA, каталог и публичное размещение относятся к следующим этапам. Для публикации нужно отдельно настроить доверенный reverse proxy и определение IP для ограничения запросов; текущий запуск предназначен для localhost.
