# Этап 2 — каталог TMDB

Актуально: фильтры, сортировки, поиск людей и фильмография, классификация анимации, рейтинг Clio и личная библиотека теперь реализованы. Итоговый статус и ограничения: [завершение MVP](completion-plan.md). Ниже сохранена история подключения; её старые списки оставшихся работ заменяет этот итог.

## История этапа

Статус: токен TMDB принят, настоящий поиск фильмов/сериалов, карточка и постеры работают через локальный Clio. Для серверных обращений TMDB локально выбран DNS по HTTPS. Полный этап каталога ещё не завершён: остаются фильтры, поиск по людям и нормализация сведений.

## Реализовано на уровне кода

- /catalog: поиск по русскому/оригинальному названию отдельно для фильмов и сериалов, популярное без запроса, пагинация до ограничения API в 500 страниц.
- /catalog/movie/:id и /catalog/tv/:id: название, оригинальное название, год, описание, постер, жанры, страны, продолжительность, режиссёры/создатели и первые 12 актёров. Шкала TMDB явно подписана; рейтинг Clio пока не имитируется.
- Серверный Bearer-токен, фиксированный адрес api.themoviedb.org, тайм-аут 10 секунд, проверка ответов Zod, отдельные состояния отсутствующей конфигурации и ошибок.
- PostgreSQL: media с уникальной парой (tmdb_media_type, tmdb_id), catalog_cache с JSON-ответами по языку. Просмотр карточки сохраняет общее произведение; никакой подстановки пользовательских списков.
- Кэш: поиск/популярное 15 минут, карточки 24 часа, повторные одновременные запросы объединяются в одном процессе, не более 20 выполняемых запросов на процесс. При сетевой ошибке/429/5xx допустим кэш не старше 7 дней с явной отметкой. Отказ ключа не скрывается устаревшими данными.
- Хранилище кэша ограничено 1000 последними ответами; старые записи очищаются при записи. При нескольких процессах дедупликация между ними не гарантируется.
- Постеры загружаются с /api/posters/:filename через сервер Clio, который обращается только к image.tmdb.org/t/p/w500. При ошибке отображается надпись о недоступности, а не вымышленный постер. Изображения не сохраняются в БД.
- Рабочая навигация по существующим разделам: боковая на компьютере, нижняя на телефоне. На главной вошедший пользователь получает ссылки на каталог и свой профиль.
- /credits: источник данных и обязательное уведомление TMDB. До публикации нужно добавить официальный одобренный логотип и проверить все условия лицензии.

## Как подключить настоящие данные

1. Создать аккаунт на https://www.themoviedb.org/signup.
2. В https://www.themoviedb.org/settings/api запросить доступ для некоммерческой разработки, прочитать и принять условия лично. Платные услуги и карта не подключаются агентом.
3. Скопировать именно API Read Access Token, не короткий API key v3, в TMDB_READ_ACCESS_TOKEN в .env.local. Ключ не отправлять в чат и не добавлять NEXT_PUBLIC_.
4. Сохранить файл; при необходимости перезапустить dev-сервер с сетевым доступом.
5. Проверить фильм и сериал: поиск → карточка → повторное открытие; перезапустить приложение и проверить повторное чтение из БД. Проверить постеры отдельно от API.

Документация: https://developer.themoviedb.org/docs/authentication-application, https://developer.themoviedb.org/docs/faq.

## Проверки и ограничения

- Прошли 9 обычных тестов (включая валидацию, дедупликацию и поведение устаревшего кэша), lint и typecheck.
- Прошли 3 интеграционных теста на PostgreSQL: auth, счётчик запросов, новые таблицы каталога. Изолированная схема проверяет разные movie/tv с одинаковым ID, запрет дубликатов и сохранение JSON-кэша.
- Миграция 0003_glamorous_silhouette.sql применена к локальной БД; существующие аккаунты не меняются.
- Production build прошёл. HTTP-проверки /catalog, поиска, неверных параметров и /credits выполнены. Неверный ID карточки отдаёт состояние not-found с noindex; при streaming Next.js статус может быть 200. Визуальная проверка браузером ещё не выполнена.
- Токен проверен настоящим запросом: поиск Interstellar вернул 20 результатов. HTTP-проверки Clio: поиск Interstellar/movie, Dark/tv и карточка movie/157336 вернули 200 и реальные данные. Тестовые данные используются только в изолированных тестах.
- Доступность из РФ без VPN не подтверждена. Перед публичным запуском нужны проверки из реальных сетей, защита запросов от спама и актуальная проверка лицензии/атрибуции.

## Остаток этапа после подключения

### Сетевая диагностика

Токен сохранён владельцем, но среда агента получает 127.0.0.1 для api.themoviedb.org, image.tmdb.org и www.themoviedb.org. Даже после сообщения об отключении Happ повторная проверка получила локальный адрес и ECONNREFUSED. Записей TMDB в hosts не найдено. Причина перенаправления не установлена, валидность токена ещё не проверена. Настройки сети не изменялись.

Для сравнения с обычной средой владельца: в терминале VS Code выполнить `npm.cmd run tmdb:check`. Команда проверяет DNS, токен, настоящий поиск и сервер изображений; секреты не выводит. Передавать в чат достаточно её результата, без содержимого .env.local. Успех ручной проверки при ошибке среды агента означает, что нужно разбирать различие окружений; одинаковый отказ указывает на общую сетевую проблему, но сам по себе не доказывает конкретного виновника.

Повторная проверка после выхода из Happ дала тот же результат у владельца. Сравнение с Google Public DNS JSON API по HTTPS вернуло публичные адреса; запрос к TMDB с сохранением оригинального HTTPS-host/SNI и проверкой сертификата вернул 200. Причина неправильных ответов системного DNS до конца не установлена.

Добавлена настройка TMDB_DNS_MODE=system|https (по умолчанию system, локально https). В режиме https сервер разрешает только api.themoviedb.org через dns.google; туда передаётся только это имя, без ключа, запросов поиска и пользовательских данных. DNS-ответ кэшируется не дольше 60 секунд с учётом TTL, частные/локальные адреса отбрасываются. Токен отправляется только TMDB, редиректы не выполняются, TLS остаётся включённым. Настройки DNS Windows не меняются. Источник протокола: https://developers.google.com/speed/public-dns/docs/doh/json.

Скрипт tmdb:check использует выбранный режим и отдельно проверяет изображения. API успешно отвечает, изображения напрямую пока не доступны. Это локально проверенный способ разрешения API, а не подтверждение доступности публичного приложения из РФ. После изменения прошли lint, typecheck, 11 обычных тестов и production build. Добавлены проверки запрета локальных DNS-адресов и отправки токена постороннему хосту.

### Постеры через сервер Clio

Прямые обращения браузера к image.tmdb.org заменены на /api/posters/:filename. Сервер использует тот же выбранный DNS-режим для двух разрешённых хостов TMDB. В запросы изображений не добавляется API-токен; Google DNS получает только имя хоста, без пути изображения. Системный DNS и сертификаты Windows не менялись, проверка HTTPS остаётся включённой.

Обработчик принимает только имя JPEG/PNG/WebP, не URL; запрещает дополнительные query-параметры, переходы по каталогам и SVG. Размер ответа ограничен 2 МиБ, содержимое проверяется по сигнатуре. Редиректы не выполняются. Ошибки возвращаются без секретов и не кэшируются. Кэш в памяти процесса ограничен 16 МиБ и шестью часами, одновременно выполняется не более восьми загрузок; одинаковые запросы объединяются. Браузерный кэш — 24 часа с ETag и ответом 304. Память между процессами не разделяется; после перезапуска сервера изображения загружаются заново.

Проверены настоящие байты постера: локальный обработчик вернул 200 image/webp, повторная условная загрузка — 304; запрос SVG и попытка передать внешний URL — 400. Это проверка локального пути, не гарантия работы публичного размещения во всех сетях РФ. До публикации отдельно проверить разрешённость выбранной схемы доставки по условиям TMDB, официальный логотип, лимиты трафика и стоимость хостинга. Новые платные сервисы не подключались.

После изменения прошли lint, typecheck, 15 обычных тестов и production build. Новые тесты проверяют недопустимые пути и содержимое, объединение загрузок, ограничение памяти, срок кэша и повторную попытку после ошибки. Владелец подтвердил, что постеры отображаются и при использовании из России. Это подтверждение конкретной проверки владельца; состояние VPN/прокси во время неё отдельно не зафиксировано, работа публичной версии и других российских сетей пока не проверена.

Проверить реальный API, постеры, русские переводы и пустые ответы. Затем добавить фильтры по году/стране/жанрам, сортировки, поиск по людям и отдельную классификацию анимации. Нормализованные genres/people/media_people и переводы добавляются вместе с этими функциями; сейчас эти сведения находятся в языковом JSON-кэше. Личная библиотека, оценки и рецензии относятся к последующим этапам.
